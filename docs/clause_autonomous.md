# CLAUSE file review and JSON delivery

The active file plugin uses `clause_delivery.FileDeliveryPolicy`. Central chooses whether one assignment or further work is appropriate. The final writer receives an action-owned filename. SP registers the validated JSON bytes from the written file or from an explicitly named complete JSON artifact body. Central selects the registered file at FINISH. Monitoring and evaluation use the same file identity, digest and JSON schema checks.

## Historical staged experiment

The following describes the superseded staged policy and its experiment settings.

Central chooses specialists and how to partition the contract. Complete separate
evidence, verification and delivery delegations. The first maps sections,
cross-references and candidate passages. The second checks quotations against the
source and decides which gaps need follow-up. A completed native observation is
required before advancing. One specialist may participate in several separate
delegations. Evidence and verification receive only read_file and grep. Completion requires an actual source read; verification must also read the registered evidence map. Each later delegation receives the registered prerequisite artifact references. Reopening evidence invalidates the previous verification. Central explicitly selects delivery after verification or requests further checks. L1/L2 retain their pinned zero/one-shot prefix.

Verification checks whether exceptions or synonymous wording reconcile a suspected conflict. Candidates merge only when they identify the same clause relationship and conflict. Each distinct verified relationship carries its own source quotation into the final JSON, including an immediately preceding printed clause identifier. The quote checker reports uniquely attributable missing identifiers and registration requires their restoration. Verification opens the registered evidence map first. On a read-only result turn, the request adapter uses a structured native envelope with findings, status and evidence gaps.

Each delivery action receives its own JSON path and write_file permission.
A read-only quote checker validates the written JSON by path and distinguishes exact quotations, whitespace differences and unlocated passages. A completed file-owning delegation can also receive a real post-write check tied to its successful write call. The checker reports findings without changing the answer. A complete native response with
a valid JSON artifact body can be persisted at that assigned path when no file
was written. Partial/blocked results cannot use the fallback. The native handler
registers that file, Central selects it at FINISH, and inference and evaluation
verify its identity, SHA-256 and schema. Historical traces stay immutable.
Native SP runs without a policy retain their standard flow.

To inspect predictions during a run or export accepted files run
`python scripts/monitor_clause_run.py RUN --export-dir ANSWERS`
(optionally add `--interval 30`). Use a fresh export directory per run.
The inference CLI can load DCC_MODEL_BASE_URL, DCC_MODEL_NAME and DCC_MODEL_API_KEY
from the ignored repository .env; explicit CLI settings and process environment
take precedence. Keep real credentials outside Git.


Read-only passes hand back their existing evidence at the native stop warning
or after 14 tool results once the source and prerequisite evidence have been
read. Incomplete coverage remains partial and Central can commission another
pass. A successful check of all passages in a newly written, owned file asks
the specialist to return its actual status. Neither transition accepts a file.
Intermediate artifacts take their family from the review phase even if Reporter performs the work; its evidence map never becomes a final report. Scoped document findings use document-read and artifact checks; generic software
regression phrases in quotations are not test failures. SP returns registered
artifact IDs and types with delegated results. An explicit new revision cites
the prior accepted artifact and its reason.

For an explicit review phase, SP preserves the role Central selected and maps the business phase to a native stage before generic routing. Role/tool permissions, action limits, and the actual evidence handoffs still apply.

In CLAUSE file mode, a full source read may include a bounded index of literal numbered mentions and line locations. A native total-tool warning gives a read-only specialist one tool-free return turn. The Qwen fallback accepts a single complete visible function block only for a currently bound Central action with valid arguments. Central chooses the next action.

A token-exhausted, unexecuted CLAUSE answer write can retry once with typed array arguments at the same path and up to three times its original generation budget (24,576 tokens maximum). The native file tool still checks the serialized bytes. The Coder receipt can register an alternate filename only after its own successful native write and matching file contents. A shell call that omits only its display label gets a default label.

When Central assigns a single new top-level JSON filename, the CLAUSE adapter uses that filename in the action’s output instruction. A complete receipt from an exclusive delegation must declare that file before its validated bytes are published to the action-owned registration path. Concurrent or pre-existing shell files cannot prove ownership.

If a native shell call exhausts its generation budget with incomplete arguments, the transport preserves its call ID and returns it to native argument validation with the required command absent. The shell never receives partial text, and the specialist can use the validation error to continue its assignment.

After a verified whole-document read, an explicitly delegated final CLAUSE answer can use the typed specialist receipt on a native total/identical-call stop warning, or once after the specialist returns without a usable body. Partial/blocked statuses and declared files retain their native handling. The response can contain an empty findings array, a complete array, or a gap. The action policy publishes complete valid answers and Central still chooses whether to FINISH.

A validated action-owned CLAUSE JSON is registered as a native generated_file across roles. Intermediate observations keep their role-specific type. A textual tool block alone cannot certify completion of an intermediate assignment.

The typed final receipt requires an actual findings array for every status. Partial or blocked receipts can carry an empty array and explicit gaps. When a fully grounded final writer exhausts its budget serializing a nonempty answer, the single recovery emits native artifact_content directly (up to 12,288 tokens). Claims with a null body do not satisfy this wire schema.

In CLAUSE file mode, a sandbox rejection of an oversized Bash command targeting an output JSON file can switch the specialist to the structured final receipt. This requires a final-answer assignment and verified complete source coverage in that delegation. Central still selects the final registered artifact.
