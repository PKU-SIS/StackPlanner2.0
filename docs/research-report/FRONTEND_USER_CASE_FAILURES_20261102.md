## 已确认的三个缺陷

1. **哈希误拒收。**材料 m158、m251 的原始文件字节 SHA 与账本完全相符；分别含 1、313 处 CRLF。`assembly._read_text` 使用 `Path.read_text()`，把 CRLF 转为 LF，再由 `_bound_text` 算哈希，所以误判文件被修改。两份材料甚至都没被大纲证据或当前草稿引用，但 `base_inputs_digest` 遍历全材料库，仍阻断整个报告。已用当前函数只读复现两处错误；保留原换行读取即可得到账本 SHA，原文件没有损坏。
2. **确定性错误反复重试。**`acceptance.next_acceptance_action` 在 technical_failed/review 分支直接再次启动审查，没有针对同一不变输入/错误的停止条件或局部次数上限。m158 校验在模型执行前就拒绝，仍不断重派相同逻辑审查动作，累计 51 次技术失败，最后由外围 60 次动作上限截停。这不等于调用了 51 次审查模型。
3. **运行成功与任务成功混淆。**最终 checkpoint 是 `error_fatal: SP action budget exhausted: 60/60`，终止文本也说明未完成；`runtime/runs/worker.py` 在图正常返回且未捕获 LLM fallback 时直接标记 success，没有识别 SP 的致命结果。报告账本 active/未交付与运行 success 因而矛盾。
