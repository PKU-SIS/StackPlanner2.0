# 成稿后多轮验收材料：冻结协议 v1

本目录只有离线材料和校验工具，没有 API 运行器。`manifest.json` 明确记录
`api_experiments_authorized=false`。本地代码/材料冻结不是付费实验、推送或部署授权。

## 文件边界

- `requests.json`：两道新题，每题七轮，只有 case ID、一万档、消息 ID 和用户原话。后续构造模型输入只允许使用 `load_public_cases()` 返回的数据。
- `evaluator_checks.json`：仅验收侧使用的逐轮模式、预期基线、有效/撤销要求和改动范围。不能进入 Central、GitAgent、Outline、Writer、记忆、检索材料或 task metadata。
- `manifest.json`：两个 JSON 的 SHA。校验失败必须停止；修订需创建新套件版本，不能覆盖冻结结果。

```bash
python scripts/validate_report_multiturn_cases.py
```

该命令只检查 schema、来源消息唯一性、版本引用、head/active 转移及 SHA，输出 API 调用数 0。
它不判断自然语言含义或报告事实是否正确。后续需要另外复核语义预期，并单独确定运行配置和费用上限。

## 两道题与七轮路径

| 轮 | 高校图书馆 RAG | 校园数字化节能运维 |
|---|---|---|
| 1 | 原生一万档报告，含运维、权限与来源要求 | 原生一万档报告，固定气候区和建筑范围 |
| 2 | 运维中增加更新频率对比 | 效果评估增加试点验收清单 |
| 3 | 保留轮 2，增加权限表 | 保留轮 2，资料时间改为 2022–2026 |
| 4 | 明确选第一版；撤销轮 2，但保留轮 3 | 明确选第一版；撤销轮 2，但保留轮 3 |
| 5 | 当前版只读来源问答 | 当前版只读证据与限制问答 |
| 6 | ExactReuse 第二版，撤销后续编辑 | ExactReuse 第三版，撤销后续编辑 |
| 7 | 从恢复版局部改运维，不能复活权限表 | 从恢复版局部改风险，保留时间范围与清单 |

版本引用按“实际产生已接受报告的轮次”解释：轮 5 和轮 6 是独立对话档案，不伪造新的生成版本。
验收侧记录 native report ID、turn ID、tree_version、draft_id、artifact version 的映射，不能把它们混为同一个编号。
后续轮绑定最初报告的实际会话 ID；模型不能自己指定宿主路径或修改版本索引。

需求标签是验收侧的语义标记，不是要求出现在正文里的字符串。
校园题扩展时间范围时撤销的是“仅限 2024–2026”的限制，已有 2024–2026 年的有效来源仍可保留。
不能把撤销时间下限错误理解成删除该区间的资料。题目只规定主题范围，不规定首轮章数、节点数或固定 node_id。

## 执行前仍需确认的事项

1. 审查并固定模型、配置、Skill/代码 SHA、原生合同、沙箱及来源工具；每例使用独立 thread/runtime/output。
2. 明确费用、token、时限与停止条件。当前没有填入可直接执行的付费配置，没有任何自动启动开关。
3. 先运行一题小样本，经检查后再决定第二题及对照。不能自动扩大到三条件全量运行。
4. 如果做对照，分别采用原生 resume 和每轮重生成，并保持同配置、同合同；明确缓存条件，不先承诺节省。
5. 真实任务失败、取消或缺少要求的交付时，记录停止轮次和全部诊断。后续题面引用的版本不存在时应停止该条轨迹，不能假装它已经接受。

## 每轮验收记录

分开记录 `preparation_ok`、executor 状态、`native_delivered`、`archive_verified` 和语义/事实结果。
修改轮必须通过原生 evidence/locator、引用、篇幅、哈希、ready review 和 Finish；不降低 9000–11000 的原生一万档范围。
只读/ExactReuse 必须有独立档案和快照，并验证 Researcher/Writer 未被调用；它们不应冒充新 native delivery。

检查完整 resolved_query 的全部有效要求、替换值和撤销项，再检查实际各章节、表格和总结。
轮 4 选旧工作基线时必须保留轮 3 的有效要求；轮 7 应使用 ExactReuse 后的 active 版本，而非最近生成的 head。
旧版全量 SHA 必须保持；未影响 canonical 草稿 SHA 保持。受影响主题对应的节点由首轮实际树建立验收映射，
必要的摘要/结论/交叉引用联动须单列，不能借联动名义整篇改写。
本套件以章节范围为主，不将整章 Writer 重写宣称为严格段落外字节保持。

保留所有成功、失败、保护停止、重试、模型请求/用量和原生事件。按实际 provider usage 和请求身份去重；
缓存已包含在输入中，不能重复相加；缺失用量不能记成 0。分列 Central、GitAgent、Outline、Researcher、Writer，
不把工具调用数、委派数、HTTP 请求数统称为轮数。耗时用逐轮单调时钟，用户等待单列。

事实/来源审查另列，不能用文件存在、原生交付、来源数量或工具无错误代替。
这些是新的自定义题，没有沿用旧批次的 RACE/FACT 成绩；如后续评分，需独立冻结适配当前需求的标准。

## 当前能力范围

覆盖成稿后的串行 ReuseAndPatch、撤销、显式旧基线、read-only 和 ExactReuse。
FreshSolve 仍使用原生未绑定的新报告入口，未在绑定报告内部实现“清空后重解”的新模式。
不包含在途并发改需求、跨报告合并、版本树 UI 或 RL。
本协议及离线通过均不表示自然语言解析或真实事实质量已经验收。
