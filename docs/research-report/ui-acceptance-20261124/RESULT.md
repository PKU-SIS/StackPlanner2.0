## 发现并处理的问题

1. 测试导入的 SQLite checkpoint 不能混用整数与字符串版本号，改为由 checkpointer 分配。
2. 导入展示消息需先经过原生 DynamicContext 初始化，否则第一条历史用户消息可能被追加到末尾，
   使最新报告绑定失效。只修正试验种子，没有修改公共 DynamicContext。
3. 实验审计在异步流关闭时，已有完整 DONE 收据仍可能误标未知。补充完整收据结算与两项回归；
   缺 DONE/用量的收据仍然未知，不凭模型回调释放预留。
4. 网页自动“推荐下一问”会产生独立 oneshot 模型请求，原报告实验审计没有这条来源。
   独立测试配置关闭 `suggestions.enabled`，不假冒为 Central 用量。
5. 下一轮可能早于上一轮 memory drain/费用核对结束；试验运行器用锁串行化完整执行与收尾。
   没有修改公共执行器或原生角色预算。
6. 网页提交的绑定消息原本没有客户端 ID。现在只给显式绑定的报告消息生成一次 UUID，
   SDK 重发同一输入时保留来源身份；普通消息结构不变。
7. 完整快照会在文件卡片显示成数百项修改。报告存档及截断的纯报告文件列表默认折叠，
   保留“查看变更”入口。普通文件和小规模首轮预览不变；仅调整展示，不过滤实际记录。

临时尝试的额外异步来源包装已移除，不在产品中增加分类器、Agent、重试或新验收关卡。
