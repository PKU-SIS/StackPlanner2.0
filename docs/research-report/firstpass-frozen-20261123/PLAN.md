# 固定实现的首次完成率与Token试验

用户同意先不叠加新护栏，测不同主题的一次完成率，并记录token开销。
本批两个主题：已验收低代码/无代码报告（全文估算9234）与单件小批制造自动化报告（9610）。各一组明确表述、一组简短指代表述，四个独立会话，固定交错顺序，共计划24条后续请求。
第一轮均只读验证并独立恢复历史成稿，不调用模型生成，也不重跑历史稳定性批次。

运行后端与四份多轮Skill固定为批次开始前版本；仅实验观察器增加数值来源记录、工具错误/子任务保护停止，不新增模型、工具或守卫。
每会话只启动一次，不人工修复、不外层重启/续跑。原生有限修正、SDK原有重试保持不变并计入消耗。前置轮失败即停止该会话后续依赖轮，下一独立会话继续。
不按前一例结果改代码、Skill、模型参数、题面或验收表；若发现问题，先完成此冻结批次的记录，另行修复。

## 判定口径

- 会话首次完成：一次用户会话运行中，计划6条后续请求全部满足原生与版本/范围程序检查。
- 无可见错误且完成：在首次完成基础上，工具错误响应和子任务保护停止均为0，观察轨迹完整。
- 每轮首次完成：分母为实际尝试；同时报告计划24条、已尝试、通过、未尝试，不能把前置失败后的未执行伪装成成功。
- 工具拒绝不自动算误拦。保存错误代码、停止原因、重复参数摘要与原生状态，事后区分合理拒绝、预算/传输中断、需求理解或执行错误。
- 只读/复用不生成新native delivery；不新增研究；其他章节canonical SHA与旧版全文件SHA保持。篇幅、引用、证据、哈希门槛不变。
- 语义与来源解释做有限差异抽查，不宣称独立事实准确率或RACE/FACT成绩。样本仅两个主题，不能外推整体可靠性。

## Token口径

逐source_run_id记录实际input/output/total与role/turn；与HTTP收据按同一来源ID对账。
缓存命中是input的子集，单列但不重复加到总token。缺usage/cache写未知并另保留已观测小计，不当0。
导出会话/用户轮/角色三层CSV，原始token保留，Markdown按万显示；失败/内部恢复/后台记忆消耗都包含。
不记录提示、正文、工具参数原文或provider私有推理；工具参数仅保留摘要hash以观察重复调用。

整批汇总token停止容量预先设为50M输入、2M输出，避免把旧试验累计量当成新会话的低额度；不改任何单角色/单请求预算。
费用guard继续沿用48元调用/50元总额度，并承接已知累计费用与旧未知请求2.162688元完整预留，不释放、不重放。
当前试次对账与全局历史未结清分别报告。串行运行，避免独立钱包并发重复发放额度。

所有题面、私有验收、基线清单、代码/Skill/SDK及统计脚本SHA在首次调用前冻结；验收表不进入模型输入。
