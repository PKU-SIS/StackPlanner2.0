# 下一步：200/50 工具预算与正常交接

状态：计划，尚未实施。按一次报告运行（run）理解总预算；一次子代理委派理解单智能体预算。

## 1. 两层预算

| 范围 | 预算 | 说明 |
| --- | ---: | --- |
| 一次报告运行 | 200 | 所有子代理共享；并行委派、重派和重试均消耗同一总量，不因再次委派刷新 |
| 一次子代理委派 | 50 | Researcher、Outline、Writer 各次委派独立计数，同时受共享 200 限制 |

- 统计实际执行的 Search、Fetch、read/write 等工具调用；一次 Search 保存 10 篇正文仍计 1 次。
- 实际执行失败也计数；工具内部的有界 HTTP 重试不重复算 Agent 工具调用，被预算拦截的请求不算已执行。
- Central 的 sp_* 控制动作沿用已有动作预算，不与执行工具混为一个计数。新 run 建立新预算，不在同一 run 的失败恢复中刷新。
- 总计数须在工具执行前原子预占，多个并行子代理共享，防止出现原先 8 次预算并发超到 11 次的情况。
- 报告模式的旧 20 次总工具限制需同步替换，图步数配套到至少 306，可取 350 留余量；不能只把表面数字写成 50。普通任务保持原预算。
- 已修改的搜索专项阈值 50 保留；重复调用、实际超时、token 保护保留。

## 2. 预算将尽时正常收尾

- 提前停止扩展检索，预留产物写入和返回结果的空间。
- Researcher 收尾时关闭执行工具，完成一次带引用的综述生成，交给原保存逻辑；不再用恢复的工具原文冒充 summary。
- 若全局预算耗尽，只执行无工具的状态收尾，保存已有产物并停止本轮；不自动刷新预算、循环重派或假称报告完成。

## 3. 再修大纲的确定字段

- material_id 有效时，source_id 从账本派生，减少模型重复填编号造成的错配。
- 对明确越过文件末尾的引用终点按真实范围规范化；未知材料或无法定位的起点才报告具体错误。
- 不把确定的编号/边界修正变成整棵大纲的反复重写，也不新增语义评分或审查 Agent。

## 4. 验证顺序

先测单体 50、共享 200、并发边界、重试不重置及纯综述收尾；再测材料/来源映射与行号规范化；最后从零重跑博物馆案例，前后端一起核对 summary 引用、大纲接受、全章节写作与交付。服务在验证准备完成前保持停止。
