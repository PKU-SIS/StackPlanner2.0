# 初始 Outline 分段测试

## 修改

- 新增 `report_read_material(material_id="m47", start_line=1, end_line=40)`：程序解析路径、核对哈希，返回真实来源编号和原始行号。仅注入报告 Researcher / Outline，避免模型复制长哈希路径。
- Outline 输入保留全部材料身份与溯源信息，去掉重复正文预览和哈希路径；初始预检索 summary 的上下文窗口从 24k 提高到 64k 字符，原文文件始终保留。三个 smoke 输入包从约 41/31/25 万字符降到 10/9/8 万字符。
- 报告 Outline 规划使用 350 图步、50 次工具；30 次工具或累计 token 到 50% 时收窄模型可见工具，保留提交、读写文件和登记工具，提示先完成大纲。累计 token 硬上限没有提高。
- 新增 `report_submit_outline(tree={...})`：传完整对象，由程序序列化和保存，不再要求把大纲 JSON 二次编码成字符串。只暂存候选，仍走原生验收；无效候选保留并返回诊断。
- 报告 Outline 默认单次输出上限为 32,768，显式 runtime 覆盖的原有优先级保留；当前 DeepSeek 接口已实测接受该上限。普通 Agent 默认行为不改。

## 测试方式

复用 `preresearch-20-markdown-v3` 的真实产物，克隆到隔离目录，重定位元数据路径并恢复 Handler 状态更新、任务记忆。只执行原生 DelegateHandler → Outline → 原生验收；登记补充研究但不执行，不调用 Researcher、Writer 或交付流程。

每条最多三次委派，每次都保留任务、可见步骤、候选和拒绝原因。原始上游文件不写回；没有绕开验收或放宽行号、来源与树结构规则。需求映射检查只验证已登记需求有对应节点，不等于原始用户要求绝无遗漏。

预备 smoke 暴露了重复上下文导致 token 耗尽，以及文件提交调用未形成可执行结果的问题；所有版本均保留。最终 smoke **3/3 首轮通过、无预算中断或工具错误**，采用来源分别为 21、31、27 个。
