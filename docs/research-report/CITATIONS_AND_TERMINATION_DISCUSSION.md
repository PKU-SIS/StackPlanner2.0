# 报告来源少、难以收尾：讨论要点

基于 `zx_sp2research`。现象来自 case 反馈，原因尚需对应运行记录验证。

已补充 [c5f99048 case 实证分析](CASE_C5F99048_CITATIONS.md)：15 个搜索候选 → 预检索保存 1 篇 → 全程保存并引用 4 篇。主要瓶颈在候选筛选、材料采集和研究覆盖；该例不支持“已保存大量文档却被 summary 丢掉”的判断。

## 1. 来源太少

**现象：整篇报告只引用约 4 个独立来源。对于当前研究报告 case，来源覆盖明显不足。**

优先怀疑三处：

- **研究偏窄**：问题拆分集中、查询相似，固定一批补充研究后没有拓展来源。
- **选证据过度收缩**：Researcher 找到多个来源，Outline 却让不同章节反复使用少数来源；Writer 只能沿用节点证据。
- **引用未完整传递**：节点绑定了多个来源，但 Writer 正文只标出少数来源，最终参考文献随之减少。

**先查三个数：成功保存的独立来源数 → Outline 各节点采用的来源数 → 报告实际引用数。** 看来源在哪一步缩到约 4 个，再决定改研究 Skill、证据选择还是写作约束。目标是扩大有效证据覆盖，不是凑出编号【5】。

## 2. 难以收尾

**初步判断：完成门禁较强，失败后的恢复与退出路径还不够明确。**

- 缺章节、缺证据、反馈未处理都会阻止交付；补任务仍依赖模型正确调度。
- 研究批次已结束、Writer 又因缺证据拒绝写作时，可能反复规划或等待。
- 同一技术错误可能重复尝试，最终耗尽预算；需要区分重复执行、等待用户和运行已结束但报告仍为 active。

## 3. 后续讨论

1. 拿一个典型 case，定位来源漏斗和最后反复出现的阻塞。
2. 按章节明确证据需求，鼓励互补、独立的来源，避免全篇依赖少数材料。
3. 无进展或重复错误时有界恢复；无法继续就保存现有结果、说明阻塞并结束本轮。
4. 改动仅作用于报告模式，不影响普通任务。
