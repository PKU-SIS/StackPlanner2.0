## 每轮怎样判断好坏

1. 从实际交付文件或 Artifacts 打开报告，不能只相信“已修改”的聊天回答。文件名可能是 report-4.md，后缀编号不等于多轮版本号。
2. 检查目标改对没有、其他有效修改是否保留、有没有越界修改、撤销项是否复活。
3. 修改应交付新版本；只读应显示回答已归档但已接受版本不变。页面“最低验收通过”只代表原生交付检查，不等于事实全对或严格只改指定内容。
4. “已编辑几百个文件”可能包含独立副本和历史材料；不要把它当成几百处正文改动。开发端可核对实际正文 diff、canonical 草稿 SHA 和旧版文件 SHA。
5. 记录最后回答、交付文件、版本号和请求原话。遇到问题先保留现场，避免连续重复发送；红色子任务要结合最终交付判断，不能单凭中途失败卡片定整轮失败。
