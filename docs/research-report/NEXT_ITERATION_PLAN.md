# 下一版计划：批量材料采集、20 次预算与写作优化

状态：仅制定计划，尚未实施。基线备份：`dd36e79`，未 push；真实运行证据归档见 [备份包](runs/live-deepseek-c5f99048-20261101.tar.gz)。

## 1. 本次问题的准确解释

- **12 次不是余额问题**：当前有效工具上限为 `min(20, (max_turns - 6) // 6)`；Researcher 的 80 步、Outline 的 78 步都算出 12。只改那个值已经为 20 的全局常量无效。
- **Search 返回 10 条也不自动等于保存 10 篇**：当前搜索只提供候选，随后逐篇 Fetch 和回读继续消耗调用次数。DeepSeek `need_content=true` 已实测返回多篇正文，需要在工具内直接保存，才能获得批量采集效果。
- **Outline 收尾中断**：那次委派发出了 `ls×1 + read_file×6 + grep×2 + write_file×3`，触发 `loop_capped`，候选树未获接收。系统保留候选，重新派发后提交成功；不是 API 没余额，也不是最终报告丢失。
- **节点补充受限还包含工具和产出问题**：一次 Researcher 确实处理了 4 个 gap，但同一个次数预算同时承担搜索、抓取、回读和失败请求，最后综述未正常产出。

## 2. 第一阶段：先解决采集与收尾

### A. 接入 DeepSeek Search / Fetch

- 新增独立提供方适配器，复用现有 Key；先在实验配置启用，保留原搜索提供方。
- Search 默认 `count=10, need_content=true`；Fetch 用于补抓正文缺失的相关页面。
- 报告模式的 `web_search` 在模型收到结果前，把每条有效正文保存到现有材料系统，分配 source/material ID；保留该工具名和现有账本，避免新建调度流程。
- 返回有界的内容摘要、材料 ID、路径及可读定位；完整正文落盘，相关原文可继续读取。没有正文的候选不冒充已保存材料。
- 去重、逐项记录成功/失败。对 408/429/5xx 有界重试；401/402 明确报鉴权/余额问题。沿用来源身份、真实工具执行记录和 gap 归属规则。

这条报告路径避开 DuckDuckGo 修改代理环境变量的代码。旧提供方的代理读/删竞争作为单独缺陷处理，不把切换入口误称为已修复旧实现。

### B. 报告 Researcher / Outline 的有效工具阈值提高到 20

- 只在报告角色装配时提高对应图步数预算；按现有保守公式至少需要 `6×20+6=126` 步，才能让有效工具阈值达到 20。
- 普通 Researcher、普通 Outline、Coder、Writer 及全局默认保持当前设置；保留重复调用、token、时间和动作边界。
- 在告警后要求优先生成完整研究综述或提交完整树，减少重复回读与重复校验。
- 增加触顶边界测试：现有中间件会在计数达到阈值时剥离当次工具请求，不能把“阈值 20”误写成“保证成功执行 20 次”。正常完成应在硬截断前发生。

继续沿用：预检索广覆盖 → Outline 汇总需求 → 一次 Researcher 补多个节点 → Outline 分配证据 → Writer 写作。数量是参考目标，不增加引用数量门禁或自动无限补研究。

## 3. 第二阶段：优化报告表述

| 问题 | 修改位置与方式 |
| --- | --- |
| 多节重复讲同一机制 | Outline 明确节点边界；Writer Skill / 提示词要求展开本节信息，已介绍概念简短承接。必要时在 Writer packet 提供有长度限制的相邻已写内容，而不是塞入整篇报告 |
| 标题称“三个问题”却列四项 | Writer 标题使用与正文一致的表述，避免无必要的数量断言 |
| 概括被包装成原文引语 | Writer 明确区分逐字引文、来源概括与分析推断；引语必须可定位 |
| 来源表出现 `material: m1` | 修改 `assembly.py` 的来源列表渲染；该文本由程序生成，改 Writer 提示词无效。正文保留 `[S<n>]` 和读者需要的标题/URL，内部材料映射留在元数据 |

保持现有整合审查角色和交付门禁，不为表述建议新增反复修订循环。

## 4. 验证与迭代顺序

1. **先做第一阶段**：补接口、材料保存、20 次有效预算及普通角色隔离测试；用相同 DeepSeek 模型和同一请求重跑，检查真实效果。
2. 重点检查：一次搜索实际保存几篇、重复/失败比例、summary 是否为完整带引用综述、是否仍 loop_capped、终稿采用多少来源、耗时与 token。
3. **再做第二阶段**：对同一报告检查重复、标题、引语和来源展示；补渲染回归。每阶段单独记录变更，便于定位增益或回退。
4. 首要验收是完整综述能正常交接、报告能收尾、普通任务不新增报告约束；10–20 篇预检索材料和主要节点 3–5 个有效来源仍为覆盖目标，不为达数虚构引用。
