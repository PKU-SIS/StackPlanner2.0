## 修复内容

1. 中枢在原 `sp_delegate` 的同一次决策中声明 `metadata.report_operation`：patch/exact_reuse/read_only。
   宿主按声明限制GitAgent终止工具，并校验reuse参数与handoff，防止完整复用进入原生改稿。无外部LLM路由、新动作枚举或首轮步骤。
2. 两份独立多轮Skill区分“完整恢复并丢弃后续变化”和“用旧基线但保留部分后来要求”；后者仍是patch。
3. 显式后续profile分配60图步，继续保留8工具和原token预算。继承perception的40步会被共享护栏折算成5次候选工具调用，可能截断终止动作；共享执行器与legacy auto未修改。
4. 只读 `evidence:<node_id>` 合并读取所选章节和受限保存材料片段，保留source/material ID、SHA、字符范围、截断/缺失信息；不检索、不改稿。
5. 试验传输校验允许官方域名的已验证公网DNS答案更新，仍要求官方host:443、TLS/主机名、凭据绑定和已审计连接作用域。

最终离线广域回归 **1139项通过**；针对性证据/DNS/费用/模式组合 **50项通过**（包含于广域数）。独立Skill格式验证通过。
首轮默认Skill、原生证据/引用/篇幅/哈希门槛保持原样；没有付费RACE/FACT评分或报告事实正确率成绩。

## 中间停止与费用边界

扩展对照共保留三次失败：

- 第一次部分保留在GitAgent读取时触发图步数/工具预算折算上限，无新native版本。
- 修正patch后第4轮通过，第5轮只读又触发同类折算上限；将一致性修正推广到全部显式后续模式。
- 第三次只读分散读取仍耗尽工具额度，后台记忆请求触发传输保护、用量未明；该试次停止，原请求没有重放。随后增加受限合并证据读取，并离线复现/修正静态DNS快照可能误拦公网IP轮换的问题。
