## 两个实质问题

### 结构请求被当作局部正文追加

第二轮明确要求在结论之后新增“补充：试点验收检查”。中枢实际派 reporter/local_edit，
理由认为这是 additive local edit。Writer 增加 `#### 补充：试点验收检查`，而结论本身为
`## 结论…`，因此小节仍在结论节点 n14 内。tree_version 始终为 2，没有新 Outline 节点，
实际未调用 Outline。该内容不能当成“独立大纲小节新增成功”。

检查器最初按新分支不存在暂停。随后保留结构失败，从已接受 t0009 继续原 query 3–5，
没有重跑前两轮或修改模型上下文。观察器改为同时识别同一 n14 中的删段与改标题，
否则会错误要求该节点只能发生其中一种变更。初始脚本／停止记录、继续说明完整保留。
这是一次人工观察器暂停，不宣称全程无人介入的全自动首次五轮通过。

### 未指定旧版时，中枢仍可任意传旧基线

第三轮中枢的 reason 承认当前交付为 r35，却在 metadata 传入 base_version_id=t0008。
local_edit.bind 直接接受已验证的旧版 ID，以“所选基线正文＋最新修改”准备副本。
由于 t0008 尚无第二轮新增小节，Writer 的新副本里本来就没有要保留的清单；结果仅保住
标题更名，却把第二轮整段表格／说明一起丢掉。第三轮 diff 明确显示整小节删除。
这是当前要求的保留关系失败，不是文件未写入、计费失败或旧文件被覆盖。

第四轮再次使用 t0008，得到与第三轮相同的 canonical 正文。因此虽然满足最终目标，
不能用它证明“撤销指定小节、保留其他改动”的能力已通过；操作前置条件已经被第三轮破坏。
程序保存／交付与用户意图满足必须分开判断，只有检查每轮 diff 才能发现这个问题。
