# 单题七轮验收预期复核（仅验收侧）

本次只选冻结套件 v1 的 `library-rag`，不修改 requests/evaluator_checks/manifest 的原始字节。
本文件不进入 Central、GitAgent、Outline、Writer、记忆、检索材料或工具任务 metadata。
它是对既有预期的解释，不是模型答案或真实报告事实标准。

| 轮 | 有效要求与目标 | 基线/状态检查 | 交付检查 |
|---|---|---|---|
| 1 | 中文一万档，高校图书馆 RAG，2024–2026，原有技术/运维/权限/评估/路线及引用要求 | 无上一版；不增加 GitAgent | 原生新交付 |
| 2 | 全部原要求 + 周/月更新频率对比 | 从第1版；完整 resolved_query 不能只是 delta | 原生新交付，影响主题为运维 |
| 3 | 保留轮2要求 + 跨院系权限/授权/审计表 | 从第2版，不能丢频率对比 | 原生新交付，影响主题为权限 |
| 4 | 选第一版；撤销频率对比；保留权限表及其他有效要求 | 必须选第1版工作基线，但需求来自当前完整有效状态 | 原生新交付；基线副本与旧 head 的差异分开看 |

| 7 | 继承恢复后的第2版，频率对比保留，澄清运维风险，不复活第三轮表 | 从 active 第2版；不能从最近生成的第4版继续 | 原生新交付；其他未受影响 canonical 草稿保持 |

## 必须避免的误判

- 首轮实际大纲决定 node ID/章节分组。不得把离线合成样本的四个节点当成真实首轮配额或固定布局。
- 逐轮检查当前完整需求、章节、表格和总结；原始消息保留。否定说明“该项已撤销”不等于旧要求重新成为待办。
- 首轮若已经包含后续要求的同等内容，不强制调用 Writer 或制造正文差异。新增的持续约束仍应明确保存在完整需求中。
- 第4轮相对于所选第一版的最小改动，与相对于旧 head 的回撤，可能不同。若第一版已有现在被撤销的附带内容，也须处理，不能只凭基线较早就宣称已经撤销。
- ExactReuse 不应删除原始对话。第7轮禁止的是第三轮新增的内容重新回到有效要求，不是把原本持续有效的隐私章节整体删除。
- 若实际首轮内容导致“只改运维、其他不动”与显式撤销冲突，或删除与9000下限冲突，应说明冲突并停止待确认，不能偷偷扩写或降低原生门槛。
- 需要用户确认/失败/取消不能记成已交付。该条轨迹停止，后续依赖不存在版本的题面不继续假跑。
- `response_only` 档案只证明保存了回复且没创建新交付；不证明用户的改稿意图已被满足。
- 程序、审查模型 ready、文件存在和原生交付都不能替代事实/来源语义审查。当前没有真实模型准确率或 RACE/FACT 成绩。

启动真实试验前仍需人工确认这份复核和账单/预算条件。任何真实结果都不能反过来静默修改冻结的题面或验收预期。
