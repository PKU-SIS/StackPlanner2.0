# 博物馆前端测试：本次实际失败链

线程 `ecc8cdcc-5f34-456a-95c6-fe827e585e14`；请求为“中外博物馆教育的现状与未来趋势”，含国家比较、分类体系与中国未来趋势。服务已停止，未改代码。

后续变更：按用户要求已将共享 `MAX_WEB_SEARCHES_PER_TURN` 从 8 调为 50，保留并发 4、连续失败 2 与总工具预算。以下记录仍为修改前的实际运行；该单项修改不代表综述收尾和大纲身份校验问题已解决。

## 1. summary 没引用

预检索成功执行 11 次 Search，保存 107 个来源、110 份材料。但另一个独立搜索中间件限制每轮约 8 次搜索；并发批次按已完成次数检查，可超到 11 次。之后一次搜索返回内部错误 `WEB_SEARCH_BUDGET_EXHAUSTED`。

模型继续使用工具，最终触发总计 20 次的硬停。框架用 `[FORCED STOP]` 和恢复的工具原文替代最终回答，再把它保存为 `summary.md`。该文件约 12k 字符、没有规范引用；它不是正常生成的研究综述。DeepSeek 搜索请求日志为 HTTP 200，未观察到余额或鉴权错误。

## 2. Outline 实际生成了候选，但没有被接受

首个候选 JSON 已包含 32 个节点，但有 37 处 material/source 编号绑定错误，并有两处行号越界。模型多处将 `mN` 配成 `SN`；实际材料与来源不是一一同号：

| 材料 | 模型填写 | 账本实际来源 |
| --- | --- | --- |
| m76 | S76 | S74 |
| m67 | S67 | S65 |
| m65 | S65 | S63 |

同一来源可以有多个材料版本，因此编号会分离。程序据此拒绝提交，错误包括 `tree.nodes[n6] evidence source_ids do not include S74`。另有 m75 仅 7 行却引用到第 15 行、m100 仅 29 行却引用到第 33 行。

第二次候选修复了大部分问题，但仍有 3 处 source 绑定错误，因 `n17/m67` 未包含 S65 再次被拒。第三次修复尚未完成，用户在 11:29:22 中断运行。因此最终 `tree=null`、草稿数为 0，前端无法展示已接受的大纲。

## 3. 根因与优先方向

- 检索规模没有收敛，模型没有及时转入综述写作；独立搜索预算与总工具硬停叠加，最后丢失了正常综述交接。
- 要求模型重复填写可由账本确定的 material→source 映射，百份材料下出现系统性错号；整树拒绝又导致长篇重新序列化和高 token 消耗。
- 优先让预检索在材料足够后进入一个明确的综述收尾阶段；再让程序派生确定的来源身份，并减少纯编号/边界错误造成的整树重做。不能只继续提高工具次数。
