A2A 协议专门被设计用来解决异构 agent 互操作、复杂问题的多 agent 协同，以及协作中安全不透明保护这三类具体问题，并作为互补层填补 agent 到 agent 通信的空档。

**异构 agent 的统一互操作标准。** 在由不同框架、不同厂商构建的 agent 生态中，A2A 为 seamless agent 互操作提供通用语言。世界上的 agent 采用多样的框架并由不同厂商构建，A2A 正是为了给这种异构环境提供统一的通信标准 [S1]。

**复杂问题的多 agent 协同。** 单一 agent 无法解决所有复杂问题，因此需要多 agent 委派子任务、交换信息、协调行动。A2A 使 agent 能够委派子任务、交换信息并协调行动，以解决单个 agent 无法完成的复杂问题 [S1]。这种协作常常跨越组织边界——另一个 agent 可能属于另一个团队、部门或伙伴组织，你的 agent 需要向外发现它们、进行协商并交换信息 [S4]。修车厂示例直观地展示了这一能力：客户通过 A2A 与 Shop Manager agent 对话，Shop Manager 与 Mechanic agent 委派诊断任务，Mechanic 再通过 A2A 与外部 Parts Supplier agent 协商下单 [S4]。

**协作中安全不透明的保护。** agent 之间协作时，双方无需暴露内部记忆、工具或专有逻辑，从而保证安全性并保护知识产权。这正是 "Secure & Opaque" 的设计取向 [S1]。

**作为互补层填补 agent 到 agent 通信空档。** MCP 是垂直的，它加深单个 agent，让 agent 连接自己的工具与资源；A2A 是水平的，它在边界之外连接 agent 与 agent [S4]。两者互补：MCP 让每个 agent 有深度，A2A 让整个系统有广度 [S4]。修车厂示例显示，Mechanic agent 内部用 MCP 调用诊断扫描仪、维修手册、升降机等工具，而 Shop Manager、Mechanic 与 Parts Supplier 之间通过 A2A 对话 [S4]。因此 A2A 填补了 MCP 仅覆盖 agent 到工具、而不覆盖 agent 到 agent 通信的这一层空档。
