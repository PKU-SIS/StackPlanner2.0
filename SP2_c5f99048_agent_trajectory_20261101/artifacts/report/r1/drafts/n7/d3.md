A2A 是一个边界明确、聚焦的协议，官方明确规定了它**不**试图成为什么 [S1]。理解这些“否定边界”有助于厘清它和 MCP 的分工。

**不是 agent 开发套件。** A2A 不像 LangGraph、CrewAI 或 ADK 那样用于构建 agent 应用；它是这些工具构建出的 agent 之间的通信层，连接用任意框架开发的智能体 [S1]。

**不是子 agent 或工具调用协议。** A2A 不规定 agent 如何与自己的子 agent 对话，也不规定如何调用工具——这类内部机制应使用开发者所选框架的原生原语，或交由 MCP 处理 [S1]。

**不是 MCP 的替代品。** MCP 标准化的是 agent 到工具的通信，而 A2A 标准化的是 agent 到 agent 的通信；两者是互补关系，而非竞争或替代关系 [S1]。

**不是即时消息应用。** A2A 不像 Slack、Discord、WhatsApp 或 Telegram 那样面向人，它是一个供自主 agent 之间进行的机器到机器协议 [S1]。

综上，A2A 有明确的应用边界：它不做 agent 开发、不规定工具调用、不替代 MCP，也不是消息应用。这些边界共同强化了它专注于 agent 间通信的定位，也正是理解它与 MCP 分工的关键所在 [S1]。
