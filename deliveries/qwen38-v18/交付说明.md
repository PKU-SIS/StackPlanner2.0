**适配修改及目的**

1. **消息和工具参数协议。** 保留全部 system 指令并统一放在消息开头，以适配本地聊天模板。工具 schema 明确要求 array/object 且不允许 string 时，对字符串容器做严格 JSON 解码；无法解码、类型不符或存在重复字段等问题仍交原有验证处理，不猜测参数。
2. **材料读取及文件工具兼容。** 对严格匹配且唯一登记的材料 ID 别名转交原生材料读取；支持 grep 读取单个文件；为虚拟用户数据根目录返回当前线程的合法入口。保留来源、哈希、原始行号及路径权限检查。
3. **搜索保护误判修复。** 本地限流、去重结果与真实搜索服务失败分别处理，避免把未发送的请求误记为服务连续失败；原搜索次数和真实失败保护保留。
4. **大纲提示和动作顺序。** 按原生任务状态选择所需技能说明章节；首次响应先选择必要原文读取，随后引导真实补研登记及完整树提交。后续轮保留完整原始合同和历史；对本次明确要求固定补研的任务，在真实登记和节点关联完成前不接受初始树。工具异常仍走原生恢复。
5. **大纲交付及校验返工。** 精简大纲统一通过 report_submit_outline 暂存，再由原生宿主验收；无效提案另存，避免破坏有效文件。用登记信息纠正确定的来源编号，合并来源和预算诊断；预算错误可提交由模型决定的小型预算补丁，随后仍对完整树执行原生校验。
6. **最终大纲漏提交纠正。** 模型只给出 proceed/notes 等完成文字、未提交有效树时，在同一个子任务内要求一次有界补交，复用现有上下文，避免直接重新委派。正常交付不会因这项机制增加模型调用。这是 v18 相对 v16 的主要新增代码修改。
7. **千问篇幅参数标定。** 保留 Outline 自选预算的方法，为千问一万字档配置 7800–9000 的内部正文预算。该区间是内部预算，不是最终全文字数；没有照搬 DeepSeek 的扩写倍率，也未把本次结果外推到千问两万或三万字档。

主要文件包括 snapshot/qwen_adapter.py，以及 snapshot/code/backend/packages/harness/deerflow 下的 sandbox、agents/middlewares、sp/report、subagents 模块和相关技能说明。changes/ 提供相对保留的 DS 一万字代码快照的累计运行源码差异，以及相对 v16 的增量差异，供逐项审阅；前者不是相对师兄原始仓库的 git diff。

两篇均完成 7 个章节，通过原生审查和完整交付核验，全文均在 9000–11000 范围。Outline 最终选定正文预算分别为 8300、8400；最终参考来源分别为 25、20 个，来源数不等于引用出现次数。

字数是引用显示和装配后的全文估算，包含标题、正文及参考文献，不是 Microsoft Word 实测。token 为整次生成累计的模型输入与输出，包含重复／缓存输入及原生纠正消耗；它不是仅正文输出 token，也未混入 RACE 评分用量。耗时采用原生完整报告图的 elapsed_seconds，未把历史失败耗时相减充作新成绩。

RACE 沿用固定的 DeepResearch Bench 清理、题目量规、参考报告和加权汇总流程，评委为 DeepSeek API 的 deepseek-flash，temperature=0、关闭 thinking。报告中的分数为目标报告相对参考报告的加权得分比例乘以 100；这是本地复用同一协议的评分，不是官方榜单成绩，FACT 未运行。评分 token 包含标准清理及评分调用，与生成 token 分开；此次共 4 次评估调用，两篇终稿及 v18 代码未改变。详细维度及用量见 RACE说明.md 和 race/。

同题历史参考：v16 低代码为 33分35秒、10384字、272.46万生成 token。v18 本次比它多 38 秒，生成用量接近。v16 的 RACE 53.25 属于旧版本旧报告，不作为 v18 分数。各次生成和检索存在波动，现有单次结果不能证明两版性能等价或跨题稳定。
